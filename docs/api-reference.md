# API Reference

Base URL: `http://localhost:8000/api/v1` (or your deployed backend URL).

Interactive docs are also auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc` once the backend is running.

Authenticated endpoints expect an `X-API-Key` header using the `api_key`
value returned when a website is created. The examples below omit it for
brevity where it isn't required by the current implementation, check
`app/security.py` for exactly which routes enforce it.

## Websites

### `POST /websites`
Register a new site.

```bash
curl -X POST http://localhost:8000/api/v1/websites \
  -H "Content-Type: application/json" \
  -d '{"domain": "example.com", "name": "Example Co", "gsc_property": "sc-domain:example.com"}'
```

```json
{
  "id": "b3f1...",
  "domain": "example.com",
  "name": "Example Co",
  "api_key": "slai_xxxxxxxxxxxxxxxxxxxx",
  "gsc_property": "sc-domain:example.com",
  "created_at": "2026-06-01T12:00:00"
}
```

### `GET /websites`
List all registered sites.

### `GET /websites/{website_id}`
Fetch one site.

## Technical SEO

### `POST /websites/{website_id}/crawl`
Crawl a list of URLs synchronously and store the results.

```bash
curl -X POST http://localhost:8000/api/v1/websites/{id}/crawl \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://example.com/", "https://example.com/pricing"]}'
```

Returns a list of `CrawlResult` objects, each with the raw checks, an
`issues` array (`code`, `severity`, `message`), and a `seo_score` (0-100).

### `GET /websites/{website_id}/crawl/latest`
Most recent 50 crawl results for the site.

## Behaviour (tracker.js ingestion)

### `POST /track`
Public endpoint called by the tracker.js SDK. Authenticated by `site_key`
in the body (the site's `api_key`), not by header, since it's called from
anonymous browsers.

```json
{
  "site_key": "slai_xxxxxxxxxxxxxxxxxxxx",
  "events": [
    {"session_id": "s1", "page_url": "https://example.com/", "event_type": "pageview"},
    {"session_id": "s1", "page_url": "https://example.com/", "event_type": "click", "x_pct": 42.1, "y_pct": 18.4},
    {"session_id": "s1", "page_url": "https://example.com/", "event_type": "section_view", "section_id": "faq"}
  ]
}
```

### `GET /websites/{website_id}/heatmap?page_url=...`
Aggregated behaviour data for one page: click grid, scroll curve, section
engagement, CTA click rate. This is what the Behaviour tab in the dashboard
renders directly.

## Search analytics

### `GET /websites/{website_id}/search-console`
Search Console metrics for every URL that's been crawled for this site. Uses
real data if `GOOGLE_SERVICE_ACCOUNT_JSON` is configured, otherwise a
deterministic demo dataset.

### `GET /websites/{website_id}/ga4`
Same idea for GA4 sessions and conversions.

## GEO / AEO

### `POST /websites/{website_id}/geo/config`
Define what to track.

```json
{
  "brand_name": "Example Co",
  "competitors": ["Rival Inc", "Acme Solutions"],
  "queries": ["best example.com alternatives", "is example.com worth it"]
}
```

### `POST /websites/{website_id}/geo/run`
Runs every configured query against every available AI provider (or the
demo provider if none are configured) and stores one `GeoRun` row per
query/provider pair.

### `GET /websites/{website_id}/geo/summary`
Aggregated visibility score, mention rates, top cited domains and a
generated insight, built from all stored `GeoRun` rows.

## Insights

### `GET /websites/{website_id}/insights?page_url=...`
The endpoint the Overview tab calls. Combines the latest crawl, behaviour
aggregates and search data for one URL into a short list of prioritised,
plain-language recommendations.

```json
{
  "page_url": "https://example.com/technical-seo-guide",
  "seo_score": 84,
  "section_engagement": [...],
  "cta_click_rate_pct": 11.0,
  "search": {"impressions": 64230, "clicks": 2810, "ctr": 0.0437, "avg_position": 7.2},
  "insights": [
    {"category": "search", "severity": "opportunity", "message": "..."}
  ]
}
```
